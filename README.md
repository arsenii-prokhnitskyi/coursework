# UnApp — аналітика та планування проєктів

Курсовий проєкт із дисципліни «Мови програмування для Web».
Тема — сайт сервісу аналітики та планування проєктів.

У проєкті реалізовано три взаємопов’язані сторінки за макетом UnApp.
Тексти присвячені плануванню завдань, контролю строків і бюджету,
розподілу навантаження команди. Інтерфейс українською мовою.

## Технології

- HTML5 — структура сторінок.
- CSS3, Flexbox і Grid — оформлення та адаптивна верстка.
- Vanilla JavaScript — інтерактивні елементи й перевірка форм.
- Python і Flask — серверна перевірка заявок та віддавання сторінок.
- Gunicorn — запуск сервера на Render.
- WebP і SVG — фотографії, ілюстрації та іконки.

## Сторінки

- `index.html` — головна сторінка з описом можливостей і тарифами.
- `blog.html` — дев’ять коротких матеріалів про планування й аналітику проєктів.
- `services.html` — опис послуг і ролей команди.
- `404.html` — сторінка помилки з переходом на головну.

## Локальний запуск

Потрібен Python 3.10 або новіший. У терміналі в папці проєкту виконати:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe app.py
```

Після запуску відкрити в браузері `http://127.0.0.1:8080/`.
Команди наведено для Windows. На Linux і macOS шлях до Python у середовищі —
`.venv/bin/python`. Для роботи серверної форми потрібен запуск через `app.py`;
звичайний Live Server відображає лише клієнтську частину.

## Що реалізовано

- Адаптивна верстка для комп’ютерів, планшетів і телефонів.
- Переходи між сторінками та розділами сайту.
- Мобільне меню та кнопка повернення нагору.
- Модальна форма з перевіркою імені, електронної пошти й опису потреб команди.
- Надсилання заявки до API та повторна перевірка полів на сервері.
- Стани очікування, відповіді сервера та помилки з’єднання.
- Закриття форми кнопкою, натисканням на фон і клавішею Escape.
- Навігація клавіатурою всередині форми та повернення фокуса після її закриття.
- Вікно з інформацією про приватність.
- Заглушка для зображень, які не вдалося завантажити.
- CSS Sprite та SVG Sprite для іконок.

Форма обговорення передає дані серверу для перевірки. Дані не записуються
у файли чи базу даних і не надсилаються менеджеру або поштою.
Форма електронної адреси залишається локальною демонстрацією без розсилки.
Показники на ілюстраціях,
тарифи та команда наведені як навчальні приклади. У блозі доступні дев’ять
матеріалів на першій сторінці; номери 2–4 неактивні.

## Структура

- `assets/css/style.css` — спільні стилі та медіазапити.
- `assets/js/main.js` — логіка інтерактивних елементів.
- `assets/images/` — зображення, іконки, спрайти та favicon.
- `app.py` — сторінки, API та серверна валідація.
- `requirements.txt` — залежності сервера.
- `render.yaml` — конфігурація розгортання на Render.
- `tests/test_app.py` — перевірки API та маршрутів.

## API

- `GET /api/health` — перевірка доступності сервера.
- `POST /api/requests` — перевірка заявки у форматі JSON з полями `name`,
  `email` та `message`. Повертає результат перевірки; звернення не зберігається.

Сайт та API працюють за однією адресою. Окремо налаштовувати адресу сервера
в JavaScript не потрібно. Сервер віддає лише сторінки й каталог `assets`;
вихідний код, звіт та внутрішні матеріали через нього не публікуються.

## Перевірка сервера

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

## Розміщення на Render

Створити **Web Service**, підключити репозиторій і вибрати гілку `main`.

| Поле | Значення |
| --- | --- |
| Language | Python 3 |
| Root Directory | Залишити порожнім |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `gunicorn app:app --bind 0.0.0.0:$PORT` |
| Health Check Path | `/api/health` |
| Instance Type | Free |

Альтернатива — створення Blueprint з наявного `render.yaml`.
База даних та секретні ключі для цього сервера не потрібні.
